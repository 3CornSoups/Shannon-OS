# ADR-0006: 移动端主导航采用底部 Tab + 更多抽屉

## 状态

已采纳（2026-08-08）

## 背景

AIOS 前端桌面端采用 VS Code 风格导航：48px Activity Bar（11 个图标竖排）+ 240px 主侧边栏（资源管理器）。在手机端这套导航不可用：

- 48px 竖栏在手机窄屏上挤压内容，11 个 36px 图标触控目标低于移动端建议的 44px 最小值
- 主侧边栏（FileExplorer 等）在手机上只能隐藏，操作入口随之丢失

目标：整个应用在手机浏览器可用，重点打磨两个聊天页（Dashboard 运维聊天 + Echo 日常聊天）。

候选方案：
1. **底部 Tab 栏**：底部固定 5 槽位，拇指可及，iOS/安卓/小程序的主流形态
2. **汉堡抽屉**：顶栏汉堡 → 滑出全量导航
3. **顶部图标横排**：把现有竖栏横置到顶部

## 决策

移动端（<768px）主导航采用**底部 Tab 栏 + 更多抽屉**：

```
🏠 聊天   💬 助手   🖥 服务器   📈 监控   ☰ 更多
```
（历史 / 模板 / 告警 / 工具 / 设置 / 关于 收进「更多」抽屉）

配套决策：
- **桌面端导航不变**：Activity Bar + 主侧边栏仅在宽屏保留
- **Tab 槽位取舍**：告警中心不占 Tab 槽位——顶栏 NotificationBell 已承担紧急告警的常驻可见入口
- **Echo 改名「助手」**：用户可见层文案「回声」→「助手」；仅改前端显示文案，技术标识（路由 `/echo`、包 `aios/echo/`、表 `echo_*`）保持不变

## 后果

### 正面
- **拇指可及 + 零学习成本**：底部 Tab 是用户已熟悉的主流形态，无需引导
- **长尾收纳清晰**：低频页面统一收进「更多」抽屉，主 Tab 保持 ≤5 槽位
- **与产品定位一致**：聊天（运维）+ 助手（日常）两个对话入口并列为最前槽位，承接 AIOS「对话优先」愿景

### 负面
- **两个聊天入口并存**：「聊天」（运维）与「助手」（日常）需用户理解区分，Tab 文案需清晰
- **底部栏占用纵向空间**：手机上聊天页可视高度减少，需配合输入区/键盘适配
- **页面级改造工作量大**：每个页面需针对移动端布局单独适配（表格→卡片、双栏→单栏、抽屉化等）

## 备选方案（未采纳）

- **汉堡抽屉**：导航被隐藏、可发现性差，切换页面多一次点击，主流已弃用作一级导航
- **顶部图标横排**：反模式——顶部应留给标题/操作；拇指难以到达；11 图标横排不直观
