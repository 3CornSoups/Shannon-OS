# ADR-0004: 合并确认层 + 风险分流

## 状态

已采纳（2026-05-12）

## 背景

PRD 中存在两层用户确认：委托决策确认（要不要委托）和风险确认（高风险任务确认）。两层确认会导致确认疲劳，大部分低风险任务也被打断。

## 决策

合并为单层确认，按风险分流：

| 风险等级 | 行为 | 用户操作 |
|---------|------|---------|
| LOW | 预判命中 → 直接委托，不弹卡片 | 零点击，可被动观察 + 随时取消 |
| HIGH | 预判命中 → 弹委托建议卡片（含风险理由）→ 用户确认后才委托 | 一次点击 |

取消按钮在委托执行期间始终可用。

## 后果

### 正面
- 减少确认打断，低风险任务自动流转
- 高风险任务依然保留人在回路中的安全控制
- 用户不会产生确认疲劳

### 负面
- 低风险自动委托可能让用户感到失控（通过始终可见的取消按钮 + 进度卡片缓解）
- 风险评级依赖 LLM 判断，LLM 可能将本应 HIGH 的任务误判为 LOW（通过预判器保守性 + 安全审计双重兜底）
