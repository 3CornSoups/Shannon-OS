# ADR-0005: 移除预判器，由 LLM 独立决定委托

## 状态

已采纳（2026-05-14）。替代 ADR-0002 中的双通道设计。

## 背景

ADR-0002 设计了「规则预判器 + LLM 感知」双通道架构，预判器通过关键词匹配在 LLM 调用前注入委托提示。该设计在实施后暴露出三个问题：

1. **关键词匹配缺乏语义理解**：「帮我重构一下简历」和「帮我重构一下这个模块」命中相同关键词，但只有后者该委托
2. **维护负担**：关键词列表与 system prompt 中的委托指南内容重复，需两边同步
3. **设计退化**：原始设计的双条件触发（关键词 + 80字符/多文件阈值）先后被移除，说明规则路线在实际使用中撑不住

## 决策

**移除规则预判器，完全由 LLM 通过 tool calling 自主决定是否委托。**

### 委托判断原则

LLM 依据统一的判断框架决策，在 `delegate_task` 工具 description 和 system prompt 中保持一致表述：

> **「改代码 → 委托 Claude Code，改系统 → Agent 自己做」**

| 委托 Claude Code | Agent 自己做 |
|------------------|-------------|
| 代码重构（跨文件语义理解） | 软件安装、包管理 |
| 模块拆分、架构调整 | 服务启停、系统配置 |
| 代码审查、依赖分析 | 日志查询、监控检查 |
| 构建脚本、CI 配置、Docker/K8s 编写 | 单条 shell 命令的运维操作 |
| 复合任务（如日志查错→定位→改代码）：Agent 先查询，拿到上下文后 LLM 再判断 | 单文件小改动 |

### LLM 决策时机

`delegate_task` 在 ReAct 循环的**每一轮**都可用。LLM 可以：
- **首轮直接委托**：用户需求明确是代码工程任务
- **中间轮委托**：先执行查询/诊断命令 → 拿到上下文 → 再决定委托

### 保留的机制

- **动态探测**（ADR-0001）：保留
- **风险分流确认**（ADR-0004）：LOW 自动委托 / HIGH 弹确认卡，保留
- **独占连接**（ADR-0003）：委托期间 SSH 独占，保留

## 后果

### 正面
- 架构简化：去掉 `pre_judger.py` 模块、`delegation_hint` 强/弱通道、预判相关 SSE 事件
- LLM 决策比关键词匹配更精准，能理解语义上下文
- 维护成本降低：委托判断逻辑只在一处（system prompt + tool description）
- 符合主流实践：Claude Code、Cline、OpenAI Codex 均不使用前置规则引擎

### 负面
- LLM 可能不调用 delegate_task 而自己硬写代码（通过 system prompt 引导缓解）
- 决策延迟增加约 0.5-1s（无预判器缓存，每次需 LLM 推理）
- 极端短输入（如「重构」单字）LLM 可能需要追问确认（通过 ask_user 工具处理）
